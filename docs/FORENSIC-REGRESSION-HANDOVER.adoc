[source,shell]
----

== Source findings underlying the negative controls

* Lexer: `plasma-parser/src/spdx/lexer.rs`, lines 118-122 silently skip unknown characters; line 149 maps parse failure to 0.
* Policy evaluator: `plasma-engine/src/eval.rs`, lines 344-349 maps `ConsistentWith` to a non-violation; `evaluate` accepts a raw Policy and schema validation is performed only through the loader.
* Facts: `plasma-engine/src/facts.rs`, lines 72-79 skip dot-prefixed directories, and lines 91-98 discard some walking errors; collection has no content hashes.
* Diff: `plasma-engine/src/diff.rs` compares file names, headers, metadata, and GitFacts but not content.
* Conditions: `plasma-engine/src/eval.rs` lines 170-181 treat absent content as false; negating that boolean can create a true condition.
* GitFacts: `plasma-engine/src/facts.rs` lines 169-185 preserve the symbolic HEAD ref but do not resolve its content hash.

== Decisions still pending (do not invent semantics)

* `Overlay.applies_to`: accepted by the schema, but unused by `effective_rules`. Its concrete selection semantics require an architecture decision before encoding a regression assertion.
* Filesystem error handling: a portable deterministic unreadable-directory fixture needs a testable traversal abstraction, because root users can bypass ordinary permission checks.
* Evidence-completeness / Unknown semantics: introduce a versioned forensic API rather than silently changing existing policy-mode truth tables.
* Creusot+Pearlite: these tests are not proofs. After correcting contracts and production behaviour, prove deontic evaluation, admission and aggregation; validate the CI prover with a deliberately false control.
